# 新规和版本变化

有新规、旧规替代、过渡期或用户要求判断会影响哪些内部控制时读本页。按[审查对象、规则效力与适用性](applicability.md)分别确认每地和每份制度的适用范围。

## 先核哪套版本在何时适用

核对正式来源及修订关系。分别记发布日期、生效日、内部批准或发布日期、旧规停用日和过渡期截止，说明在审查基准日适用哪一版。现行与未来生效规则分别登记；未来生效事项可提前设计、培训和准备系统，但不得在实施日前默认改变客户体验或拒绝交易。旧版与新版并存时，按主体、场景和时间检查是否正常分段执行，明确旧控制停止日期。需要判断历史补录、补报、重核、迁移或补救时，从过渡、溯及条款或正式澄清查具体范围。新业务、存量关系、在途交易和持续义务分别判断；持续关系、资料过期或持续尽调触发可能要求重新评估。“不追溯”结论须由法律意见或监管书面确认支撑，不能只写“不适用”。

## 按变化查影响位置

| 外规变化 | 重点查的内部落点 |
| --- | --- |
| 新增义务 | 主制度与本地细则、流程触发、岗位权限、表单、系统以及留痕。 |
| 删除、替代或澄清义务 | 哪些旧规则失去原依据、哪些仍有其他适用依据，以及执行动作是否实质变化。 |
| 定义、主体或对象变化 | 客户、账户、交易或数据范围，核术语、字段、分类、进入和退出流程，以及下游用到该分类的控制。 |
| 阈值、期限或公式变化 | 口径、起算和临界值，核系统参数、取数或计算方式、审批例外、报表和历史重算。 |
| 责任、权限或流程顺序变化 | 授权矩阵、职责承接、独立复核、系统权限、模板和培训。 |
| 报送、留存或传输变化 | 报送字段、数据来源、时限、审批、报表生成和更正。另查归档、备份、日志、权限、供应商与跨境路径。 |
| 原则或抽象标准变化 | 用官方解释确定动作、触发、例外和记录，再查现行做法能否达到要求。 |

基于现有材料判断是保持现有控制、澄清执行、修改制度还是联动流程、表单、系统、权限、合同、培训或报送。说明哪项适用、哪项仍待核。涉及实施、测试和责任安排时查[整改设计与验证](remediation.md)。
