# 外规内化审查方法

每项外部条款按“对象与效力 → 适用性 → 最小义务 → 抽象条款解释 → 控制目标 → 内规映射 → 差异识别 → 影响传导 → 整改验证”分析。后一步使用前一步的结论，不得由法规标题、关键词命中或制度名称直接跳到差异和修改建议。

## 读原件并逐条正查

模型按外规原件顺序整理外部条款，保留条号、续段、定义、例外和附件位置，再逐项查找相关内规。工具只辅助提取和检索，是否相关、适用及存在差异均由模型回到原文判断。Word 提取只剩段落时先回原件核对显示编号；确无条号时用章节、页码或原文首句定位。

### 第一步：先确定分析对象

先回答“谁在被分析”，再读义务。记录分析基准日、法律主体、监管身份、法域和监管主体、牌照或注册或批准或豁免、实际业务、客户、数据、系统、输入材料及排除事项。

香港总行、上海分行、其他分行或子公司分别建卡。集团统一发文只证明存在集团文件，不能替代当前主体的牌照和实际业务判断。牌照、业务、系统或数据位置未确认的项目标待核，不写成已适用或已排除。

开始分析前评定输入质量：**完整**是外部规则、适用对象、业务场景、内部制度和辅助资料齐备；**基本可用**是缺少部分内部制度，但仍可建立外部要求清单和查找缺口；**不足**是缺少法域、主体、业务或具体规则，不能凭空映射。把缺口和受影响范围记入待核，能确认的部分继续分析。辅助资料会提升分析质量，但不改变输入质量等级。

涉及具体客户身份、账户、交易、风险评级或可疑活动，或者要求确定是否违规、承担刑事责任或获得豁免时，只整理与制度审查相关的可确认事实，不作确定法律结论，并将相关事项列入交付后人工复核。缺少适用法域、责任主体或业务背景时记录所缺事实及影响，其余分析继续。用户要求永久存储、跨会话调用或对外传播内部机密材料，或者要求把草案、公开咨询或未来生效规则按现行规则处理时，不擅自执行，将边界和需确认事项留到交付后集中提示。

### 第二步：确认规则身份与效力

对每条外部材料确认发布主体、发布日期、生效日、当前状态、文件层级、适用法域、约束力、过渡期和原件位置。区分现行、修订、废止、被替代、部分失效、草案和未来生效。

按材料实际性质区分法律、行政法规、部门规章、监管指引、通函、问答、司法裁判、集团政策和合同。低层级材料不得推翻高层级规定；集团加严写集团标准，合同或代理行要求写合同义务，不改写成当地法定义务。只有标题或摘要时，先取得原文，不补造条款。

现行与未来生效规则分别记录。未来规则可以提前设计、培训和准备系统，但不得在实施日前默认改变客户体验或拒绝交易。涉及历史业务时先查溯及力、持续义务和过渡条款；“不追溯”结论须有法律意见或监管书面确认支撑，不能只写“不适用”。新增、修改、删除和澄清分别登记，具体处理见[新规和版本变化](regulatory-change.md)。

### 第三步：完成四层适用性筛选

按[审查对象、规则效力与适用性](applicability.md)依次判断：

1. **主体是否适用。** 条文义务对象是否对应当前法人、分行、部门、员工、外包方或系统。两地分别形成结论。
2. **牌照和业务是否适用。** 当前主体是否实际拥有所需牌照、注册、批准或豁免，是否实际开展该产品、客户、币种、渠道和地域业务。“银行原则上可以做”不等于当前主体已经获准或实际开展。
3. **场景是否触发。** 核开户、授信、付款、跨境、美元清算、高风险客户、数据出境、外包、系统变更、交易异常、资料变化和风险等级变化等条件及例外。条件适用须写条件是否已经满足。
4. **是否存在属地外溢。** 分清当地直接义务、合同或代理行义务、集团政策义务和事实影响。支付核币种、参与方和清算路径；数据核主体、目的、字段、系统、远程访问、接收方和所在地。

输出适用、条件适用、不适用或待核及依据。未通过适用性筛选的条款不进入差异判断；待核只影响相应事项，其余分析继续。

### 第四步：拆出可逐项对照的要求

把确认适用的条款拆成最小义务单元。每项必须能单独回答“谁在什么条件下，对什么对象做什么，何时完成，留下什么证据”。

| 义务要素 | 分析时要确定的事实 |
|---|---|
| 主体 | 哪个法人、分行、部门、岗位、外包方或系统承担义务。 |
| 对象 | 哪类客户、实益拥有人、账户、交易、数据、系统、报告、记录或供应商。 |
| 条件 | 哪个业务事件、风险等级、名单、所有权关系、跨境路径或系统变化触发；持续义务何时开始和结束。 |
| 动作 | 识别、核验、审批、拦截、监测、复核、报告、保存、删除等具体动作，以及执行、复核和交接顺序。 |
| 时限和频率 | 起算点、截止点、实时、逐笔、定期或事件触发；法规未给数值时保持待核。 |
| 例外 | 豁免、替代、延后、过渡或人工放行的条件、授权和期限。 |
| 证据 | 应生成或保存的档案、审批、日志、报表、回执和审计记录，以及保存期限和检索方式。 |
| 禁止或后果 | 条文同时规定禁止、处罚或报告后果时一并保留，用于分析失效场景。 |

一条外规含不同对象或动作时分别判断，定义、否定、门槛、例外和时点不得拆丢。每项义务用外规版本、条款及子项、适用主体和场景定位。

### 建立稳定 ID 和追溯关系

在工作记录中为外部条款、控制和内部条款建立稳定 ID，不以文件标题或页码作为唯一标识：

- **外部条款 ID：** `法域-监管主体-主题-序号`，指向具体版本和最小义务；
- **控制 ID：** `机构-主题-控制序号`，指向控制目标和实际控制活动；
- **内部条款 ID：** `机构-文件简称-章节号-条款号-版本号`，指向内规及执行位置；
- **差异 ID：** 用于连接最小义务、控制缺陷、整改动作和验收证据。

原文位置仍是判断依据，ID 用于跨文件引用、正反查复用、版本更新和整改后回写，不替代条号、页码或原文。真实编号未知时使用临时 ID 并标“待正式编号”，不得伪装成真实制度编号。

### 边审边记

每份外规维护可回读的工作记录，处理一条就记录一条：

- **外规定位。** 条款号、附件位置或原文首句，以及该条实际义务。
- **内规查阅。** 相关内规原文及位置；未相关、不适用或待核的，写明理由。只有实际看过材料才记为已查。
- **义务与适用。** 复用前四步结论，记录法律主体、监管身份、牌照或业务、触发场景和最小义务。
- **覆盖判断。** 写明内规实际做了什么、由哪个岗位或系统执行、证据在哪，以及完全覆盖、部分覆盖、术语不匹配、无控制、冲突或待核。无差异也留记录，供内规回查复用。

未读、未核或材料缺失的范围留在待审或待核，不把检索无命中写成全文无规定。

## 解读和术语材料

第五步处理抽象及模糊条款。风险为本、合理怀疑、持续监察、适当措施、及时报告、充分理解、商业合理性、必要措施、确保有效和采取一切合理步骤等表述，不得原样复制为分析终点。

1. **先整理用户辅助资料。** 用户提供司法解释、监管问答、术语表或行业指南时，识别文件格式，提取结构化条目，建立 `J-USER-序号` 或 `T-USER-序号`，并在工作记录建立关键词、法域、业务、术语和条款关联索引。保留来源文件、条目 ID、原文位置、适用主体、明确和未明确部分及证据要求。检索时使用精确匹配、模糊匹配、语义匹配和跨语言匹配多路召回，候选仍须回原文判断，不把相似度当作适用或等效依据。
2. **抽象条款先查用户资料。** 用户资料未覆盖时，再查正式司法解释、立法说明、监管问答、官方指引、通函、执法案例、法院裁判和主管部门口径。按[可执行化指引](materials/operationalizing-ambiguous-clauses.md)先找行为条件，再找量化阈值，最后找证明责任；同时确认发布者、版本或日期、法域、适用主体和效力。
3. **把解释落成执行要求。** 写清哪个主体在什么条件下，由谁采取什么动作，何时完成，如何处理例外、升级与复核，留下什么证据。只有监管鼓励、行业基准或内部业务解读时，不写成更高层级的法定义务。
4. **统一术语并保留映射。** 优先采用用户术语表的标准称谓；内部制度使用不同表述时，记录“内部表述—标准术语—英文—适用法域—对象和行为差异”。术语用于连接，不直接证明等效；同名可能对应不同义务，异名也可能指向同一控制，仍须回原文比较。用术语表的“常见误解”检查内部制度是否存在同类错误，用解释条目的“明确部分／未明确部分”区分必须做、可以做和仍待管理判断的事项。
5. **没有权威数值时不补造。** 确实无法细化的，明确写“未发现可直接适用的权威解释”，保留管理判断、书面标准和复核记录，写清触发条件、例外审批和待核事项。
6. **冲突要有解决路径。** 用户资料相互冲突时列出双方原文，暂按最新版本或更权威来源处理并标为假设，将优先级确认事项留到交付后集中提示。用户资料与外部最新监管指引冲突时，同时列明双方观点，以最新监管指引为优先核对方向并标出用户资料待更新处。集团与本地规则冲突时保留双方适用依据和冲突点，将监管澄清以及临时控制、过渡控制和永久控制的决策列入交付后集中提示，不口头择一，也不简单停留在待核。

引用解释时保留外规原文及位置，同时写用户资料或解释材料名称、条目 ID、发布者、版本或日期、条款或页码，并说明它解释的是哪条外部条款、确认还是澄清或改变原理解、适用法域和主体、影响制度还是流程或系统或培训、能否形成确定标准、是否已过时或被替代，以及对当前判断的作用和证据等级。输出位置见[问题记录](results.md#问题记录)。

### 从制度条款核到控制动作

第六步从最小义务推导控制目标，再查既有控制。控制目标写清要防止的风险或达到的结果，例如“及时识别制裁命中”，不能写“加强制裁合规”。为每项控制目标分配控制 ID。

先描述失效表现，再确定控制责任人和执行人、预防或发现或纠正等控制类型、自动化程度、频率、证据类型和补救动作。控制描述必须能回答“什么触发下，由哪个岗位或系统，对哪个对象完成什么动作”。

强制控制不得建议化；人工例外核原因、授权、复核和期限；四眼原则核至少两名具权限人员独立复核；补偿控制核独立性、及时性、证据、有效期和退出条件。

### 第七步：建立外规、控制和内规映射

先按六个维度组合检索，不能只搜法规标题或用一次全库关键词搜索代替映射：

- **主体维：** 机构、部门、岗位，以及执行人与复核人。
- **业务维：** 开户、授信、付款、外汇、财富管理及本次实际业务。
- **对象维：** 客户、账户、交易、员工、供应商、数据及对应系统字段。
- **动作维：** 识别、审批、监测、记录、报告、保存、核验、拦截、复核、删除及先后顺序。
- **控制维：** 政策条款、流程节点、岗位职责、审批权限、系统规则、名单筛查、额度限制和独立复核。
- **证据维：** 日志、表格、审计报告、系统截图、审批、样本和报送记录。

搜索范围除制度正文外，还包括操作手册、授权表、岗位手册、检查清单、客户声明、系统参数说明、培训材料、合同模板、数据地图、供应商文件、旧版流程和审计整改台账。记录关键词组合、文件范围、命中位置、映射结论、未命中原因和补充搜索词。

映射支持多对多：一条外部条款可对应多项控制，一项控制可对应多条内部条款，一条内部条款也可承接多项控制，同一控制还可落入多个业务系统和流程。政策、流程、模板、系统、接口、权限和岗位分别记录实际承接位置，不只连制度标题。

按“监管义务—控制目标—既有控制—缺口—证据”作判断：

1. **完全覆盖。** 触发、对象、动作、时限、例外和证据均有承接，仍核版本和培训。只有制度文本，而义务所需的流程、模板、权限或系统承接缺失时，不得标为完全覆盖；系统控制是否必需仍由适用义务决定。
2. **部分覆盖。** 写清已经承接的动作及缺少的具体要素，不写“相关制度已涵盖”。
3. **术语不匹配。** 区分只是称谓不同，还是对象、触发或执行结果不同。
4. **无控制或冲突。** 无控制须查全文、附件和引用文件；冲突须比较同一主体、业务、对象、触发和时点的实际动作。
5. **等效或补偿控制。** 核适用依据、控制目标、对象、触发、结果、授权、独立复核、期限、证据和退出条件。
6. **待核。** 明确缺法律主体、监管身份、牌照、实际业务、相关制度、系统配置还是运行样本。

按[场景与控制证据](control-evidence.md)区分设计、执行和持续运行三个证明层次。按本次业务阅读[银行业务与控制核对点](banking-controls.md)，但不以核对点替代适用原文。

### 记录义务与控制的判断

每项需要作出覆盖判断的义务留下：

```text
外部条款ID及最小义务｜适用主体与场景｜控制ID、控制目标及属性｜内部条款ID及实际执行位置｜映射理由｜覆盖结论｜证据或待核事项
```

同一法律主体和业务场景下的同一项义务，正查与反查复用并更新同一判断。内规没有正式编号时用章节、页码或原文首句作工作位置，标待正式编号，不伪装成真实条号。

## 逐项反查

从每项适用的独立义务出发，先确认当前内规是否负责承接，再查全文、交叉引用及可取得的附件。每份内规遍历所有输入外规，包含正查未命中但可能由本制度承接的义务。正查和反查使用同一义务、适用性结论和术语解释。

- 承接责任来自内规目的和适用范围、明确授权或其他制度指向。集团义务按当地制度或集团流程的实际分工核对。
- 按六维继续查等效动作、附件、同义词和上下游控制。没有原词或未看到相关文件时，不直接判整项缺失。
- 同一外规条款含多项义务时逐项判断，部分落实与整项缺失不得混写。
- 已有条款但缺少对象、条件、动作或证据要素的，列条款差异；只有当前内规明确应承接且全文、附件和引用文件均无对应控制时，才列制度级缺口。

拟列整项缺失时，留下适用及承接依据、已查文件和版本、六维检索范围、最接近控制及其不能覆盖的理由。明显相关承接文件未取得时标待核。

需要验证运行时另做双向追踪：从规则到内规、流程、系统和交易证据，确认控制被执行；从异常交易回到制度，确认系统发现和处置位置。双向追踪不代替上述全量义务反查。

## 定级并整理问题

第八步比较最小义务与既有控制，识别差异；第九步判断影响、风险和整改。先完成事实比较，再分类和定级，不因主题重要或条文字眼严重直接判高风险。

### 从笔记形成最终问题清单

每完成一批，将候选发现与正反查记录和现有问题清单对照，形成可回指的记录：

```text
差异ID｜主承接制度与位置｜区域｜适用主体与场景｜外部条款ID及最小义务｜控制ID及既有控制｜内部条款ID｜具体差异｜差异类型｜影响与风险｜整改动作｜责任角色与截止日｜验收证据｜不确定性及人工复核人
```

1. **先定主承接制度。** 按映射和实际整改责任确定目标 Sheet；引用或受影响的其他制度写进分析。
2. **再定区域。** 已有对应内规条款但覆盖不全、冲突或缺要素，列条款差异；明确应承接而整项无控制，列制度级缺口。
3. **跨制度归并。** 同一主体、场景和控制缺陷只在主承接位置出现一次。不同法域、主体、义务或整改动作确有差异时分别列出。
4. **处理矛盾和反证。** 拟写分类、归属或等级与笔记不一致时，回到原文和映射复核。后续找到其他承接、例外或反证时，修改、移动或撤销记录。

### 差异类型

差异类型回答“问题是什么形态”，风险等级回答“影响有多严重”，两者分别判断。每条最终问题只填一个主差异类型，其他表现写入分析。漏洞通常列入制度级缺口，其余类型通常列入条款差异，最终以最小义务及对应内规条款是否存在为准。

| 类型 | 成立条件 | 必须留下的举证 | 排除和易错点 |
|---|---|---|---|
| 漏洞 | 外规明确适用，当前内规应承接，但政策、流程、模板、系统和监督措施均未承接，也没有覆盖该义务的例外审批。 | 外规位置、承接依据、已查文件及版本、六维检索范围、最接近控制及未覆盖理由。 | 未找到原词不等于漏洞；其他制度已承接、业务未确认或材料未取得时先写去向或待核。 |
| 差距 | 已有条款或控制但未完整覆盖，例如只覆盖部分客户或产品、有制度但无保存期限、有监测但无升级处置，或只有一般要求而无例外、升级或负责人。 | 内外规原文、已覆盖部分、缺少的具体要素及影响场景。 | 措辞不同或未逐字复述不等于差距；共同覆盖的部分不重复列。系统控制是否必需须有适用依据。 |
| 冲突 | 外规与内规、不同内规或制度与操作手册、培训材料、系统参数在同一主体、业务、客户类型、触发和时点下不能同时执行。 | 双方原文、文件层级、版本、生效时点、适用主体和互斥动作。 | 更严格不一定是冲突；不同法域、主体或时点的差异不直接判冲突。 |
| 重复控制 | 多处重复规定已造成或可能造成责任不清、版本不同步、审核负担增加或员工不知道以哪个版本为准。 | 重复位置、引用分工、责任或版本差异及实际执行影响。 | 主制度与细则正常分工、一致引用不列问题；不得无差别删除。 |
| 过度控制 | 内部加严缺乏法规、合同或集团依据，并无依据扩大范围、造成不相称阻塞、权责倒置或数据过度收集。 | 加严条款、依据核对、受影响对象及误拒、业务阻塞或流程负担事实。 | 高于外规本身不是缺陷；有依据且与风险相称不列。 |
| 责任缺口 | 已有控制动作，但责任人不明确、责任与授权不匹配、无备份或升级机制，或现有安排无法证明控制执行。 | 控制链、岗位和授权材料、断点及无法接住的场景。 | 未提供岗位材料只说明待核，不直接认定无人负责；执行人和控制所有者不能混写。 |
| 证据缺口 | 控制可能已经执行，但无法证明何时、由谁、按什么标准完成，如何审批和处理例外，记录保存多久或日志能否检索。 | 留证义务或流程、现有字段和留存条款、缺失证据及对追溯或调取的影响。 | 用户未上传运行材料不等于制度证据缺口；未交付范围留待核。 |

### 风险和影响传导

沿“外部规则变化 → 控制要求变化 → 内部制度或系统缺口 → 业务执行偏差 → 客户、交易、报送或监管影响”说明差异怎样产生影响，不停留在制度名称。

逐项回答：不改会发生什么、哪些业务首先受影响、是否影响存量客户和在途交易、是否需要历史补救、客户通知、监管报告或暂停业务，以及哪些证据能够证明整改完成。分别判断制度与流程、系统、模板与文档、数据与报送、培训与人员、合同与外包、组织与授权、历史业务与客户的影响。证据不足时写潜在影响或待核，不断言处罚、补报或业务暂停已经发生。

- **高风险。** 同时满足至少两项：直接违反现行法律或监管规则；涉及客户资金、数据或重大交易；影响开户、付款、制裁、反洗钱或重要数据；存在监管处罚或业务中断风险；已有监管关注、审计发现或客户投诉；无制度、无流程且无系统控制；不同内部文件存在明确冲突；无法提供任何执行证据。
- **中风险。** 已有控制但覆盖不足、责任或频率不明、制度与操作手册版本不同、记录不完整或保存期不明、系统可执行但缺乏监测，或权威解释改变原有理解但尚无明确违规证据。
- **低风险。** 纯文字优化、重复定义、编号调整、引用更新、培训表达调整或不影响实质控制的标准优化。完全覆盖且无需调整的事项不写成问题行。

### 建议怎么写

收到新规或确认差异后，依次判断无需修改、解释澄清、制度更新、流程更新、模板更新、系统更新、培训更新、合同更新、报告更新或组织架构更新。结论是“更新制度”时，继续下钻到具体条款、控制、岗位、流程、表单、系统参数、权限和证据。

- 写清新增、修改或删除的条款，以及相应业务动作、执行人、复核人、触发、时限、例外和记录。重复条款指定主文件和引用关系；冲突指定唯一生效版本及旧条款失效依据。
- 每项差异在工作记录指定责任角色、截止日、验收证据、不确定性和人工复核人。正式整改按控制工件明确唯一最终负责者，执行角色可多个但须拆到具体工件；未确认的岗位和日期标待确认，不虚构。
- 区分法律或监管必须改、机构建议改和无需改。集团政策、合同或代理行要求引起的改动标明来源性质。
- 替代或补偿控制写明批准、有效期、临时控制、升级人、证据和退出条件。
- 按[新规和版本变化](regulatory-change.md)处理新旧版本、过渡和历史业务，按[整改设计与验证](remediation.md)写明责任、变更工件、正例、反例、边界、人工例外、独立验证和复测证据。

### 整改关闭与映射维护

整改完成不能只看文本已经修改。按[整改设计与验证](remediation.md)核对制度批准、流程修改、系统或参数更新、人员培训、新旧版本切换、历史业务补救或豁免的证明；阻断缺陷未关闭不得上线，关键缺陷须独立复测。

关闭后回写法规状态、外部条款版本、控制矩阵、内部条款映射、差异台账、旧条款失效表、系统参数影响、培训影响、审计测试程序和整改关闭证据。任一必要环节缺证时，不标为“已关闭”。

写入前回读引文，确认事实、主体、牌照和业务、差异类型、等级及建议说的是同一项最小义务。证据不足的事项标待核，HTML 继续交付已经确认的问题。输出字段和交付要求见[问题记录](results.md#问题记录)。
